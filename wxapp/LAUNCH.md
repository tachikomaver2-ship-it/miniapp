# LarkyGO 上线操作手册（云开发版）

> 代码已全部就绪：AI / 登录 / 内容安全已迁云函数，GLM key 只存在云端，前端零密钥。
> 本工程已完成上线合规四链路：隐私协议、微信登录、支付（演示降级）、内容安全。

---

## 第 1 步：部署云函数（2 分钟）

1. 微信开发者工具打开本工程，左侧资源管理器找到 `cloudfunctions/larky-server`
2. 右键 `larky-server` → **「上传并部署：云端安装依赖（不上传 node_modules）」**
3. 等待上传完成（控制台显示「上传成功」）
4. 验证：模拟器 → ✦ AI Tab → 随便问一句「上海有什么活动」
   - 回复正常 = 云函数 + GLM 全链路 OK
   - 聊天头部显示「· ✨ GLM」徽标

> 无需配置任何域名白名单（云开发走内网调用，免备案）。

## 第 2 步：后台配置（mp.weixin.qq.com，10 分钟）

1. **用户隐私保护指引**：设置 → 服务内容声明 → 用户隐私保护指引
   - 收集的信息只勾：**位置信息（可选）、微信openid、相册（仅识图时）、剪贴板**
   - 与代码实际用到的权限保持一致，多勾或少勾都可能被驳回
   - 「隐私政策」链接填部署后的 PRIVACY_URL（或指向小程序内置协议页）
2. **头像**：设置 → 基本设置 → 小程序头像 → 上传 `logo/app-icon-square-1024.png`
3. **类目**：设置 → 基本设置 → 服务类目
   - 首选：**生活服务 → 其他生活服务**（活动信息展示，资质要求最低）
   - 注意：先不要选「票务」类目（需要营业性演出许可证）；当前购票为演示模式

## 第 3 步：上传代码（1 分钟）

1. 开发者工具右上角 → **「上传」** → 版本号 `1.0.0` → 备注「首发」
2. 弹出的「代码质量分析」有提示可忽略（不影响）

## 第 4 步：提交审核（5 分钟填写）

1. mp.weixin.qq.com → 版本管理 → 开发版本 → 刚才上传的 1.0.0 → **「提交审核」**
2. 页面信息：
   - **服务类目**：生活服务 → 其他生活服务
   - **功能页面**：首页
   - **截图**：用之前准备的 5 张实机截图
   - **演示说明**（审核备注栏，可直接复制）：
     > 本小程序为城市娱乐活动信息展示与 AI 助手工具。用户可浏览 12 个城市的 5 类活动信息（运动/音乐/户外/表演/美食），通过 AI 对话查找活动、用 AI 助手创建活动草稿。购票功能为界面演示，不产生真实交易；支付环节为模拟弹窗，无微信支付调用。
   - **测试账号**：无需
3. 提交 → 等待审核（通常 1-3 天，最快几小时）

## 第 5 步：审核通过 → 发布

版本管理 → 审核通过 → **「发布」** → 全网用户可搜到

---

## 常见审核驳回原因（提前规避）

| 风险点 | 现状 | 规避方式 |
|---|---|---|
| 隐私指引与实际权限不符 | 指引未填 | 第 2 步已列明，严格按实际勾选 |
| 「模拟支付」被判涉支付资质 | 购票为演示 | 审核备注已声明「不产生真实交易」；如仍被驳，可暂时隐藏购票按钮 |
| 内容安全 | 已接入 msgSecCheck/imgSecCheck 云调用 | 已达标 |
| 类目不符 | 生活服务-其他 | 活动信息展示定位明确 |
| 诱导分享/虚拟支付 | 无 | — |

## 发布后建议

- 去智谱后台（open.bigmodel.cn）给这个 key 配置用量告警（当前 key 曾在前端暴露过，建议发布后**重置一次 key**，只更新云函数里的 GLM_KEY 一处）
- 云开发控制台 → 云函数 → larky-server 日志，可看每次 GLM 调用
- 真实支付上线需：商户号 + 绑定 + 云函数补统一下单（见 cloudfunctions 内注释）
